Android update checks no longer wait for each other.

**Fixed in 0.3.2**

- **A new release is offered in a dialog, including in a chat.** The app reads the release page when it starts, instead of waiting up to six hours after the last check. Dismissing the dialog keeps it closed for that release until the next app session.
- **The background check always runs.** The six-hourly check was skipped when the app had checked recently, which could delay the update notification.

- **Desktop updates also open a proposal.** Review the update or choose Later; installation still requires your action.
- **Opening the update dialog refreshes the release information.** A background notification cannot leave the dialog showing an older cached version.
- **Notifications can be retried after permission is restored.** A blocked notification is no longer recorded as sent.

**Install**

| Platform | File |
|---|---|
| Linux x86-64 | `1loop-0.3.2-linux-amd64.tar.gz`: extract, run `./1loop` |
| Windows 10 1809+ x64 | `1loop-0.3.2-windows-amd64.zip`: extract, run `1loop.exe` (or `1loop-software.cmd` without OpenGL) |
| Android 8+ | `1loop-0.3.2.apk`: open it on the phone |
| Server | `1loop-server-0.3.2-linux-amd64` or `…-windows-amd64.exe`: see docs/SERVER.md |

Installed apps update themselves: **Settings → Updates**. Phones on 0.2.0 or 0.3.0 install this APK by hand once.

**Android warning:** Google Play Protect may say 1loop is harmful, or recommend a scan. 1loop is installed from outside the Play Store and can run a Debian environment, run commands and control the phone when you allow it. The code is open in this repository. Choose *Install anyway* or *Install without scanning*.

Windows SmartScreen may show *Windows protected your PC*: choose *More info → Run anyway*.

The full guide: docs/INSTALL.md in the repository.
